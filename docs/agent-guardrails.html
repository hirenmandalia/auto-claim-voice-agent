1. Scope and identity

What the agent is allowed to talk about, and what it already knows about the caller before the first word.

Auto claims onlyPrompt Code Eval

Collisions, hit-and-run, theft of or from the vehicle, vandalism, glass, weather, fire, animal strikes, and towing or rental caused by one of those. A home, health, travel, life, or pet loss is declined kindly with a pointer to the right insurer, and no facts are collected for it. The agent is not a general assistant: it declines shopping, repair advice, quotes, legal or medical questions, jokes, and chat, and steers back to the claim.

Enforced: the SCOPE block of the system prompt, plus a deterministic backstop. If the classifier still sees a non-auto loss, apply_scope_gate forces the route to out_of_scope and the app hides Review & submit. Emergencies keep priority. FNOL_AUTO_ONLY=off restores the multi-line demo. Tested in tests/test_scope_gate.py.

The caller is already knownCode Prompt Eval

The app passes the signed-in policyholder's name, policy number, and vehicle when the claim starts. The agent greets by first name, never asks for the name or policy number, and looks the policy up in the background on its own. Contact is a single preference question, phone or email, because both are on file.

Enforced: app_context is sanitized to four allowed keys and injected as app state before the first turn; the extractor is told a stated preference is a complete contact answer, and the validator drops any "specific email address" style gap. Live eval common_checks fails any transcript where the agent asks for a name or policy number.

English, and only EnglishCode Eval

The spoken voice and both on-screen transcripts are pinned to English. If the voice still drifts, the line is cut mid-sentence on the phone, dropped from the transcript, and the agent is steered back in English. A single stray foreign glyph from the transcriber is stripped silently; three or more characters count as drift.

Enforced: language_code and language_codes in the live config; the NON_LATIN guard in the transcript stream. Observed before the fix: a mid-call switch to Spanish, and a Devanagari transcript. Rules test test_language_pinned_for_speech_and_both_transcripts.

2. How the agent speaks

Rules about the shape of each reply. Most of these came directly from phone tests where the agent repeated itself or narrated its own machinery.

Speaks first, by nameCode Eval

When the claim screen connects, the agent greets the caller by first name and asks whether everyone is safe. Nothing is pre-written; the greeting is generated and spoken.

Enforced: the server sends a greeting cue the moment the live session is ready for a fresh in-app claim. Live eval greeting: spoken within 12 s, contains the first name and a safety question, no second unprompted line within 6 s.

Replies right away; note-taking never blocks speechCode Prompt Eval

The agent acknowledges what you said in the same turn it files notes. The claim-notes pipeline runs in the background and the screen refreshes when it lands.

Enforced: the sync_claim_packet tool returns instantly with the last finished notes and a "may lag one turn" note; the pipeline is kicked off with request_update(). Before this, the agent waited 20 to 30 s per turn. Live eval latency_single_reply: first words within 4 s (typically about 1 s).

One reply per thing you sayCode Eval

Background results never make the agent speak a second time. If the agent handled a turn with tool calls only and said nothing, the server prompts one reply after 1.2 s so it cannot go mute.

Enforced: packet-sync results use SILENT scheduling; nudge_if_silent covers the mute case. Policy lookup and photo pins stay WHEN_IDLE so a tool-first turn can still continue into speech. Rules test test_packet_sync_is_silent_other_tools_continue; live eval counts replies per turn.

Never narrates its own machineryCode Prompt Eval

No mention of models, prompts, notices, app events, tools, processing, or waiting for a response. If nothing new has happened, it says nothing. Silence is always preferred to narration.

Enforced: a hard rule in the prompt, and the META_TALK guard on the transcript stream: a matching line cuts the phone's audio within a fraction of a second, is dropped from the transcript, and the agent is steered back once per 20 s. Ordinary insurance phrasing such as "processing your claim" is allowed. Observed before the fix: "To give the model enough time to respond to your most recent prompt, please wait patiently." Rules test test_meta_talk_guard; live common_checks scans every transcript.

Never restates, never re-asksPrompt Code Eval

Each time it speaks it says something new. Every notes result hands it an explicit list of what is already known: date, location, what happened, contact preference, name, policy. To confirm one, it states the fact and asks "is that right?" rather than asking fresh.

Enforced: already_known_do_not_ask_again in every sync_claim_packet result. Rules test test_already_known_list_is_populated; live eval flags "when did it happen" after the date was given.

Asks only for checklist itemsCode Prompt Eval

No repair estimates, receipts, invoices, medical records, mileage, or anything not on the checklist. If you answered an item before being asked, it is not asked. When you have an item, it is collected on the spot, on camera where possible, never deferred to "later" or "the app".

Enforced: prompt rules, plus the OFF_CHECKLIST_ASK guard that cuts such a question mid-sentence and steers back. Live eval full_call_closes and every scenario fail on an off-checklist request.

Never invents statusCode Prompt Eval

Before the claim may close, the agent never says the packet was submitted, sent for review, that a reviewer will look at it, or that someone will get in touch. Asked "are we done?" too early, it says it is finishing its notes and will confirm in a moment. Nothing is submitted until the caller taps Review & submit.

Enforced: the PREMATURE_CLOSE guard, active only while closing is not yet allowed. Observed before the fix: "your claim packet is now being submitted for a human review." Live eval probes with "Are we done here?" before the closing.

Never speaks a silence placeholderCode

"No speech", "silence", or similar transcription placeholders are never spoken or shown, on either side, and never trigger a reply.

Enforced: the SILENCE_PLACEHOLDER guard. This one deliberately does not prompt the model again, because a prompt is what produced the line.

Never promises coveragePrompt

Policy details describe what is on the policy, not what will be paid. No promises of coverage, payment, liability, benefits, or approval.

Enforced: prompt rule from the original demo, kept verbatim.

3. Turn-taking

Who speaks when. This is where most of the phone-test failures lived: re-asking over the caller's answer, interrupting on room noise, and prompting the model while it was mid-sentence.

Voice detection is deliberately insensitiveCode Eval

The live model is told to require clear speech before it decides you started talking, and to wait a beat before it decides you stopped.

LOWstart-of-speech sensitivity
LOWend-of-speech sensitivity
300 msaudio kept before speech start
900 mssilence that ends your turn
Enforced: _realtime_input_config; FNOL_VAD_SILENCE_MS adjusts the pause. Rules test test_voice_detection_is_low_sensitivity.

You can interrupt; the room cannotCode Manual

Barge-in is on: talk over the agent and it stops and listens. While the agent is speaking, the phone passes only loud, sustained speech through; everything quieter is sent as silence so the audio stream stays continuous. The mic also stays muted for a short tail after the agent stops, because speaker echo trails the audio.

0.08 RMSloudness to count as interruption
430 mssustained before it passes
700 msecho tail after playback
0.006 RMSnoise floor when agent is quiet
Enforced: echo cancellation and noise suppression on the mic; the gate in mobile.js; FNOL_BARGE_IN=off makes the agent finish every sentence. Echo behaviour can only be verified on a real phone speaker.

The model is never prompted mid-sentenceCode

Every app-side prompt to the model (a re-ask, a lighting notice, the closing cue) waits until the model has finished generating and the phone has finished playing. The phone reports both playback start and end to the server.

Enforced: wait_until_idle() in front of every prompt. A prompt that lands mid-response is what produced the "please wait for the model" line.

Silence gets one gentle re-ask, and your voice cancels itCode Prompt Eval

After the agent asks a question, the clock starts when its audio finishes playing. If the phone hears nothing from you for ten seconds, the agent checks in once, warmly, in different words, with no new topic. If you stay silent after that, it waits. If you make any sound in the window, the re-ask is cancelled before it is sent. If the agent's reply had no question at all, the same ten seconds produce the next checklist question instead, so the call cannot stall.

"Take your time, there's no rush. I just want to make sure you're safe right now."
Enforced: follow_up_if_quiet, driven by the phone's playback and activity messages; one check per claimant turn, never a third ask. Live evals quiet_reask (fires at 10 s or later, rephrased, no third ask) and voice_cancels_reask.

4. Call order and closing

The call has three phases in a fixed order, and the closing line is gated by code, not by the model's judgement.

Phase 1

Core facts

Six fields. Name and policy come from the app.

  • What happened
  • When
  • Where
  • Injuries
  • Phone or email
Phase 2

Checklist, by kind of loss

One item per turn, each asked once. "I don't have it" is a complete answer. The list depends on what happened, read deterministically from the caller's words.

  • Glass, weather, animal strike, single vehicle: photos only
  • Vandalism, theft: photos, police report
  • Two-party collision, hit and run: photos, police report, other driver and witnesses
Phase 3

Closing

Only when the server says closing_allowed. Nothing is asked after it.

  • Short summary
  • The closing line
  • Review & submit appears

Closing is gated on core facts, and every checklist item being coveredCode Eval

A checklist item counts as covered once either side has mentioned it, so volunteering "no police report" before being asked is enough. Documents and third-party details can never block the close; only a missing core fact can. The claim does not close early, and it cannot get stuck.

"Your claim packet is ready. You can review it in the app, and once you submit it, an adjuster will get started on it."
Enforced: closing_allowed in summarize_workflow_for_voice, computed from the six core fields and transcript keywords; the validator drops document-type items from blocking facts. Observed before the fix: a closing followed by "do you have a repair estimate?", and a call that never closed because "other driver's insurance details" stayed listed as missing. Rules tests in ClosingGate; pipeline fixture other_driver_fled_closes; live eval full_call_closes.

An injured caller gets a closing tooCode Prompt Eval

When someone is hurt the closing adds that the claim is flagged for urgent human review and that they should get medical care, then the standard closing line. The agent gives that medical reminder once, with no care instructions and no questions about who was treated; those details go to the adjuster's packet.

Enforced: the escalation branch of the closing rule and the closing prompt; injury follow-ups are hidden from the agent's open items once injury status is known. Observed before the fix: an injured caller asked "are you done?" and heard "finishing my notes" twice with no closing.

What the caller has is collected before the closeCode Prompt Eval

If the caller says they have photos or the other driver's card, the claim cannot close until the agent has asked to see it on camera. "I can't show it right now" is then a fine answer; silently skipping it is not.

Enforced: offered_but_not_yet_collected in the packet summary blocks closing_allowed until a camera request appears in the agent's lines. Observed in the first scenario run: the "volunteers everything" caller mentioned photos and a card and the agent closed in two turns. Rules test test_offered_photos_block_closing_until_asked_to_show; scenario volunteers_everything.

A declined claim shows as out of scopeCode Eval

When the agent declines a non-auto loss, the route becomes "Auto claims only" even though no facts were collected, so the app never shows a declined call as "in progress".

Enforced: SCOPE_DECLINE on the agent's line sets the route; the classifier-based gate still covers the case where facts were collected first. Scenario out_of_scope_home.

The app flips to "closed" the moment the line is spoken, and stays closedCode Eval

Review & submit appears as soon as the closing line is said, without waiting for another notes cycle, and a later loose end in the notes cannot hide it again.

Enforced: the server pushes state when an agent turn matches the closing phrasing. Found by the first run of the eval suite. Live eval checks state.closed.

A natural beat while the notes finishPrompt Code

When the last item is covered but the notes are still being finalized, the agent says it is finishing up its notes and goes quiet; the phone plays soft keystrokes and shows "taking notes". The closing follows when the notes land. The re-ask is held during this window.

Enforced: all_items_covered in the sync result; the keystroke cue in mobile.js.

5. Safety and routing

Safety first, every timePrompt

If anyone may be hurt or in danger the agent gives emergency guidance regardless of topic, says a human representative should review, and escalates the packet. "No one is hurt" is a negative fact, not an emergency.

Only a confirmed injury or hazard escalatesCode Eval

An injury the caller has not answered about yet is noted for the adjuster, not escalated. Before this rule, "Escalated to a person" flashed on ordinary fender-benders in the seconds before the caller answered the opening safety question.

Enforced: policies.py rule SAFE-001 fires on status present only; uncertain raises the non-escalating SAFE-002. Pipeline fixtures injury_unanswered_no_escalation and real_injury_escalates; rules tests in EscalationRules.

6. Camera and evidence

The camera streams one frame per second while on. The agent's eyes are the adjuster's eyes, so what it claims to see is checked independently.

Every distinct view is pinnedPrompt

A new angle, a close-up, a different part of the vehicle, or a photo held up to the camera each count as new. The agent keeps pinning until you are done showing things, and never re-pins an unchanged view. Photos shown on a screen or on paper are accepted as evidence; the agent judges the picture, not the screen.

Captions are independent, and "confirmed" is earnedCode

Each pinned frame is captioned by a separate vision call that is told to ignore any instructions inside the image and to describe only what is visible. A photo is marked Confirmed only when that caption supports what you said. Only the server can mark evidence as received; the language model cannot.

Poor lighting is detected three ways and prompted onceCode Eval

Phone cameras boost gain in the dark, so a dark room reads as murky grey rather than black. The server flags a frame as too dark on any of three signals, turns the phone's overlay amber with the fix, and asks the agent to request light. A dark pin is kept as a placeholder, tagged "Too dark, retake", never confirmed.

< 60mean luminance (0 to 255)
< 10 %pixels reasonably lit
> 55 %pixels in deep shadow
3 framesin a row before the prompt
12 svision usability check interval
45 scooldown between prompts
Enforced: frame_is_dark on every frame, camera_quality_watch while the camera is on, and a lighting judgement on every pin. Rules test test_dark_frames_detected_bright_frames_pass; live eval dark_camera.

No sketchesCode Eval

The incident-sketch tool is not offered to the model, and the prompt says sketching is unavailable. FNOL_SKETCH=on brings it back.

7. Data handling

Memory only, thirty minutesCode

A claim lives in the server's memory and is forgotten after 30 minutes without activity. Nothing is written to disk unless you download the packet. A live connection ends after 20 minutes and can be resumed.

Reachable only on the local networkCode Eval

The server refuses any client that is not on a private network address, and only when FNOL_ALLOW_LAN=1 is set. The phone connects over HTTPS with a certificate issued for the Mac's Wi-Fi address.

Enforced: client_ok and local_host; rules test test_lan_mode_accepts_private_addresses_only_when_enabled.

What leaves the MacCode

Your audio, camera frames, and the transcript go to Google's Gemini API and nowhere else. The policy lookup is a local mock directory. The demo files nothing with any insurer.
